BRAINFORZE / SCOPE & QUALITY GATE

รับเฉพาะงานที่
ตรวจสอบและส่งมอบได้จริง

ระบบนี้ช่วยแยกงานมาตรฐานที่มีขอบเขตชัดเจน ออกจากงานที่ต้องประเมินเพิ่มหรืออยู่นอกขอบเขต ก่อนรับเงินหรือสัญญาวันส่งมอบ ไม่มีการรับประกันผลลัพธ์ที่ควบคุมไม่ได้ เช่น กำไรจากการเทรด หรือผลจากแพลตฟอร์มภายนอก

กติกาหลัก: งานจะเข้า “ส่งมอบทันทีหลังชำระเงิน” ได้เฉพาะสินค้าดิจิทัลสำเร็จรูปที่ผ่านการทดสอบและมีไฟล์ส่งมอบพร้อมอยู่แล้วเท่านั้น งานสั่งทำต้องผ่านการตรวจบรีฟ ขอบเขต ราคา เวลา และ QA ก่อนเสนอรับงาน ห้ามแสดงว่ารับงานอัตโนมัติหากยังไม่มีหลักฐานรองรับ

ขอบเขตแต่ละหมวดงาน

EA / MT5

ต้องทดสอบก่อนส่ง
  • รับได้: กลยุทธ์ที่ระบุชัด, คู่เงิน/สินทรัพย์, Timeframe, entry/exit, risk limits และ input ที่รองรับ
  • ต้องผ่าน: Compile, test cases, ไม่มี error ที่ทราบ, ตรวจสัญญาณเข้า/ออก, ทดสอบ spread/commission และรายงานข้อจำกัด
  • ไม่รับ: รับประกันกำไร, “ไม่ขาดทุน”, กู้พอร์ต, กลยุทธ์ที่ต้องใช้ข้อมูล/โบรกเกอร์ที่เข้าถึงไม่ได้ หรือ HFT ระดับสถาบันด้วย EA MT5 ทั่วไป
  • ส่งทันที: เฉพาะ EA สำเร็จรูปเวอร์ชันที่ผ่าน QA และมีเอกสาร/ไฟล์ครบ

เว็บไซต์ / Landing Page

มาตรฐานตามแพ็กเกจ
  • รับได้: หน้าเว็บตามจำนวนที่กำหนด, responsive, เนื้อหา/ภาพที่ลูกค้ามีสิทธิ์ใช้ และฟังก์ชันที่ระบุ
  • ต้องผ่าน: ลิงก์, ฟอร์ม, มือถือ/เดสก์ท็อป, accessibility พื้นฐาน, build/deploy และตรวจข้อมูลลับ
  • ไม่รับ: ฟังก์ชัน backend ที่ไม่ได้รวม, ระบบธนาคาร/บัญชีภายนอกที่ไม่มี API หรือการรับประกันอันดับ SEO/ยอดขาย
  • ส่งทันที: เทมเพลตสำเร็จรูปที่ทดสอบแล้ว; เว็บสั่งทำต้องรอ QA และ deploy

กราฟิก / โลโก้ / Branding

ไฟล์ตามสเปก
  • รับได้: จำนวนชิ้น ขนาด สี รูปแบบไฟล์ และจำนวนรอบแก้ที่กำหนด
  • ต้องผ่าน: ขนาด/ความละเอียด, เปิดไฟล์ได้, ตรวจข้อความและสิทธิ์ใช้งาน asset
  • ไม่รับ: ลอกงานมีลิขสิทธิ์, ใช้เครื่องหมายการค้าโดยไม่มีสิทธิ์ หรือรับประกันจดทะเบียนเครื่องหมายการค้าได้
  • ส่งทันที: สินค้าเทมเพลตที่พร้อมดาวน์โหลด; งานเฉพาะบุคคลต้องตรวจ proof

วิดีโอ / Motion

จำกัดความยาวและ asset
  • รับได้: ความยาว/อัตราส่วน/ความละเอียด/คำบรรยายตามแพ็กเกจ และใช้ฟุตเทจที่มีสิทธิ์
  • ต้องผ่าน: ตรวจเสียง ภาพ เฟรมสุดท้าย ตัวสะกด และไฟล์ export
  • ไม่รับ: งานที่ต้องถ่ายทำจริงโดยไม่มีทีม/อุปกรณ์, likeness ที่ไม่มีสิทธิ์ หรือเพลง/ฟุตเทจละเมิดสิทธิ์
  • ส่งทันที: stock template ที่สำเร็จแล้วเท่านั้น

พรีเซนเทชัน / เอกสาร

จำนวนหน้าแน่นอน
  • รับได้: จำนวนสไลด์, ภาษา, รูปแบบไฟล์, โครงเรื่อง และข้อมูลอ้างอิงที่ลูกค้าให้
  • ต้องผ่าน: ตรวจสะกด, ตัวเลข/สมมติฐาน, การแสดงผล, ฟอนต์และลิงก์อ้างอิง
  • ไม่รับ: ข้อมูลเท็จที่ขอให้แต่งเป็นจริง, คำแนะนำวิชาชีพที่ต้องมีใบอนุญาต หรือข้อเท็จจริงที่ตรวจสอบไม่ได้
  • ส่งทันที: ชุดเทมเพลตมาตรฐานที่ระบุชัดว่าตัวเลขเป็นตัวอย่าง

AI Art / 3D / สื่อโฆษณา

ตามข้อจำกัดเครื่องมือ
  • รับได้: คอนเซปต์ ขนาด อัตราส่วน จำนวนภาพ และรูปแบบส่งออกที่ระบุ
  • ต้องผ่าน: ตรวจข้อกำหนดภาพ, artifact, ความละเอียด, ข้อความสำคัญ และสิทธิ์การใช้เชิงพาณิชย์ตามเครื่องมือ
  • ไม่รับ: สำเนางาน/บุคคลโดยละเมิดสิทธิ์, งานผิดกฎหมาย หรือความแม่นยำระดับ CAD/วิศวกรรมที่ยังไม่มีการตรวจรับรอง
  • ส่งทันที: เฉพาะชุดสำเร็จรูปที่ตรวจแล้ว

Dashboard / Data

ต้องกำหนดแหล่งข้อมูล
  • รับได้: UI, charts, filters และข้อมูลจำลองที่ระบุชัด
  • ต้องผ่าน: คำนวณตัวเลขเทียบชุดทดสอบ, สถานะว่าง/ผิดพลาด, responsive และสิทธิ์เข้าถึง
  • ไม่รับ: ข้อมูลสดจากบัญชีภายนอกโดยไม่มี connector/API, ระบบการเงินที่ยังไม่ผ่าน security review
  • ส่งทันที: UI demo แบบ static เท่านั้น ไม่อ้างว่าเชื่อมข้อมูลจริง

Automation / ระบบเชื่อมต่อ

ต้องตรวจความเสี่ยง
  • รับได้: ขั้นตอนที่มี API, credentials จัดเก็บปลอดภัย, test environment และขอบเขตสิทธิ์ชัด
  • ต้องผ่าน: happy path, failure path, retry/idempotency, log, access control และ rollback
  • ไม่รับ: ขอรหัสผ่านธนาคาร, ข้ามระบบยืนยันเงิน, ทำงานโดยไม่มีสิทธิ์ หรือสัญญาว่าบริการภายนอกจะไม่ล่ม
  • ส่งทันที: ไม่ควรส่งอัตโนมัติก่อนทดสอบ integration จริง

งานอื่น / Custom

ประเมินแยก
  • หากไม่มี checklist, เกณฑ์รับงาน, แหล่งข้อมูล หรือวิธีทดสอบที่ชัดเจน ให้เป็น “รอตรวจสอบ”
  • ถ้าต้องพึ่งบริการภายนอกที่ยังไม่เชื่อมต่อ ให้แจ้งลูกค้าก่อน ไม่รับชำระแบบอัตโนมัติ
  • หากอยู่นอกความสามารถ/สิทธิ์/งบ/เวลา ให้ปฏิเสธอย่างชัดเจนและไม่รับเงิน

มาตรฐานสถานะคำสั่งซื้อ

สถานะความหมายอนุญาตให้รับเงิน?ส่งทันที?
READY_TO_SELLแพ็กเกจคงที่, ไฟล์พร้อม, QA evidence ผ่าน, ราคา/สิทธิ์ชัดได้ เมื่อระบบชำระเงินผ่าน E2Eได้หลังยืนยันชำระเงินจริง
NEEDS_REVIEWบรีฟกำกวม, ต้องประเมินเพิ่ม, มี dependency ภายนอกยังไม่รับอัตโนมัติไม่ได้
OUT_OF_SCOPEทำไม่ได้ตามข้อกำหนด/ไม่มีสิทธิ์/เสี่ยงเกินนโยบายไม่ได้ไม่ได้
QA_FAILEDไม่ผ่าน test, deliverable ไม่ครบ หรือหลักฐานไม่ครบหยุดและแจ้งผู้ดูแลไม่ได้
PAID_VERIFIEDตรวจยืนยันการชำระจากแหล่งที่เชื่อถือได้ยืนยันแล้วเฉพาะ READY_TO_SELL ที่ผ่านทุก gate

ตรวจบรีฟเบื้องต้น

แบบฟอร์มนี้คัดกรองเบื้องต้นในเบราว์เซอร์เท่านั้น ไม่ได้สร้างออเดอร์ ไม่ได้อนุมัติราคา และไม่ใช่การยืนยันว่ารับงานแล้ว

หมายเหตุการเปิดใช้งาน: เกณฑ์นี้เป็นหน้าแนวทาง/คัดกรองฝั่งหน้าเว็บเท่านั้น การบังคับใช้จริงต้องอยู่ใน Backend โดยตรวจสิทธิ์ ราคา version ของแพ็กเกจ สถานะ QA และผลยืนยันการชำระเงิน ห้ามเชื่อค่าที่ส่งมาจากเบราว์เซอร์เพียงอย่างเดียว ตาม Master Plan ปัจจุบัน C.22 — BF + Cost + Payment E2E ยังเป็นโฟกัส และ Pricing Policy ยังอยู่สถานะ CONFLICT — REVIEW REQUIRED จึงยังไม่ควรเปิดรับชำระเงินจริงแบบอัตโนมัติจนกว่าจะแก้สถานะและผ่านหลักฐานทดสอบ
